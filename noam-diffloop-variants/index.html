Suggestion-diff review: three directions

All three honor the same interaction mandates from the plan. They differ in where the review lives and how much attention each decision gets. Open each full view, it is interactive: ] / [ move, A accepts, R rejects.

  • Inline diffs + gutter markers
  • Persistent review bar, never toasts
  • ] [ A R keyboard grammar
  • Batch review + trust tiers
  • Presence decay states
  • Conflict cards
  • Fixed 8-color agent palette
  • 44px targets, real focus rings
  • Welcome moment, accept transition, digest voice

My recommendation: ship A, keep B as a power mode

A is the spec's child: context stays visible, the queue is the natural home for batch review and trust tiers, and it is the cheapest to build from the plan. B's focused session is the right answer for clearing a backlog of twelve suggestions, so keep it as an explicit mode rather than the default. Steal C's chip bar for narrow windows and the eventual mobile story.

Variant A

The Rail

Cream editor with a persistent right review rail. Suggestion queue, batch controls, trust tiers, and the digest all live in the sidebar. Closest to the written spec.

Pros
  • Everything visible at once. The queue doubles as an audit trail, and batch plus trust controls sit next to the items they affect.
  • Inline context never leaves the screen. You always see the note around the diff.
Cons
  • The rail eats editor width and squeezes the note on smaller windows.
  • A tall queue can feel like a second inbox, and reviewers may process cards top-down instead of reading the note.

Variant B

Review Session

Dark, full-screen focused mode. One proposal at a time, large diff, prominent keyboard hints, progress bar. Esc returns to the note.

Pros
  • Highest attention per decision. The keyboard-first flow shines when clearing a backlog.
  • The mode boundary makes each accept feel deliberate, which fights click-through fatigue.
Cons
  • Hides the surrounding note, so accepting without full context can mislead.
  • Mode switching costs add up for a single quick accept. Can feel heavy for one suggestion.

Variant C

The Drawer

Editor-first. A slim bottom bar holds suggestion chips; an expandable drawer reveals the focused diff, batch, trust, and digest. Minimal and dense.

Pros
  • The editor stays king. The chip bar is glanceable and scales to many suggestions without a tall sidebar.
  • Best information density. Details expand only when needed.
Cons
  • Two-step reveal (chip, then drawer) adds friction to every single review.
  • Conflict cards feel cramped in the drawer, and it competes with the keyboard for vertical space.
